# Configuration

The app reads environment variables at process startup and vocabulary files
from `config/`. Docker Compose loads `.env` automatically.

Start with:

```bash
cp .env.example .env
chmod 600 .env
```

For a production deployment, leave generated secret fields empty and run
`./deploy.sh`. The script fills them without changing API keys or tuning values.

## Required settings

| Variable | Purpose | Example |
| --- | --- | --- |
| `DOMAIN` | Public hostname used by Caddy and deployment output | `captions.example.com` |
| `ADMIN_PASSWORD` | Admin dashboard login password | Generated by `deploy.sh` |
| `SESSION_SECRET` | Independent HMAC key for 24-hour admin sessions | Generated by `deploy.sh` |
| `DEEPGRAM_API_KEY` | Deepgram speech-to-text credential | `dg_...` |
| `OPENAI_API_KEY` | Primary translation-provider credential | Provider-specific |
| `ROOMS` | Comma-separated room slugs | `main-stage,workshop-1` |
| `TOKEN_<ROOM>` | Bearer token for one room | Generated by `deploy.sh` |

`DOMAIN` must be a bare hostname, without `https://` or a path. It may be
`localhost` for development, but public microphone capture requires HTTPS.

Passwords and room tokens must be at least 16 characters. `SESSION_SECRET`
must be at least 32 characters. Generated values use 24 random bytes represented
as 48 hexadecimal characters.

## Rooms and room tokens

Room slugs may contain groups of lowercase letters and numbers separated by
single hyphens, and may be up to 64 characters.

The token variable name is derived by uppercasing the slug and replacing
non-alphanumeric separators with underscores:

| Room slug | Token variable |
| --- | --- |
| `main-stage` | `TOKEN_MAIN_STAGE` |
| `room-1` | `TOKEN_ROOM_1` |
| `workshop-2026` | `TOKEN_WORKSHOP_2026` |

Example:

```dotenv
ROOMS=main-stage,workshop-1
TOKEN_MAIN_STAGE=
TOKEN_WORKSHOP_1=
```

Run `./deploy.sh` to populate empty token fields. To rotate a token, replace its
value and recreate the app:

```bash
docker compose up -d --force-recreate app
```

Old capture and overlay URLs stop authenticating immediately after the new
container starts.

## Server settings

| Variable | Default | Description |
| --- | --- | --- |
| `PORT` | `3000` | Node.js HTTP and WebSocket port. Compose fixes the container port at 3000. |
| `ADMIN_PASSWORD` | none | Admin login credential. |
| `SESSION_SECRET` | none | HMAC signing key for expiring admin session cookies. |

The Docker deployment exposes only Caddy on ports 80 and 443. The Node.js port
is internal to the Compose network.

## Translation providers

The translation client calls:

```text
<BASE_URL>/chat/completions
```

The endpoint must support streamed OpenAI-compatible chat completions.

The `OPENAI_*` names describe the API protocol used by the client. They do not
require OpenAI to be the primary provider. For example, when Cerebras is
primary, `OPENAI_API_KEY` contains the Cerebras key; the actual OpenAI key goes
in `FALLBACK_API_KEY`.

### Primary provider

| Variable | Default | Description |
| --- | --- | --- |
| `OPENAI_API_KEY` | none | Required provider credential. |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | API root without a trailing slash. |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Model used for drafts and, by default, finals. |
| `OPENAI_EXTRA_BODY` | empty object | JSON object merged into every request body. |
| `OPENAI_SERVICE_TIER` | empty | Optional OpenAI service tier, such as `priority`. |

OpenAI example:

```dotenv
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=sk-replace-me
OPENAI_MODEL=gpt-4.1-mini
OPENAI_EXTRA_BODY=
OPENAI_SERVICE_TIER=
```

### Production-tested: Cerebras primary with OpenAI fallback

The original conference production configuration was:

```dotenv
OPENAI_BASE_URL=https://api.cerebras.ai/v1
OPENAI_API_KEY=your-cerebras-key
OPENAI_MODEL=gpt-oss-120b
OPENAI_EXTRA_BODY='{"reasoning_effort":"low"}'
OPENAI_SERVICE_TIER=

FALLBACK_BASE_URL=https://api.openai.com/v1
FALLBACK_API_KEY=your-openai-key
FALLBACK_MODEL=gpt-4.1-mini
FALLBACK_EXTRA_BODY=
```

Use valid JSON for `OPENAI_EXTRA_BODY`. Single quotes around the complete JSON
value work with both the Node dotenv parser and Docker Compose.

#### Why this arrangement

In September 2026 tests from the original Sao Paulo VPS, OpenAI first-token
latency was usually the slowest part of the live draft path. Measurements were
roughly 500–900 ms across the tested OpenAI models, and
`OPENAI_SERVICE_TIER=priority` did not produce a measurable improvement in that
environment.

On noisy transcripts from the real event, Cerebras `gpt-oss-120b` with
`reasoning_effort: low` was comparably faithful while responding in roughly
305 ms, versus 751 ms for OpenAI `gpt-4.1-mini`. That made Cerebras the better
normal translation path for captions that needed to grow several times per
second.

OpenAI was deliberately kept as the fallback rather than removed. If Cerebras
timed out or failed, a slower recovered final caption was preferable to no
final caption. The app aborts a stalled primary final request and retries it
through `FALLBACK_*`.

These results are historical and provider performance changes over time. Use
the latency script and real-event recordings to validate the choice for your
location, account tiers, and current models.

Generic compatible-provider example:

```dotenv
OPENAI_BASE_URL=https://provider.example.com/v1
OPENAI_API_KEY=primary-provider-key
OPENAI_MODEL=provider-model-name
OPENAI_EXTRA_BODY=
```

### Separate final provider

When `FINAL_API_KEY` is present, live drafts use the primary provider and
completed phrases use this provider:

| Variable | Default | Description |
| --- | --- | --- |
| `FINAL_API_KEY` | empty / disabled | Enables the separate final provider. |
| `FINAL_BASE_URL` | `https://api.openai.com/v1` | Final provider API root. |
| `FINAL_MODEL` | `gpt-4.1-mini` | Final-caption model. |
| `FINAL_EXTRA_BODY` | empty object | JSON fields merged into final requests. |
| `FINAL_SERVICE_TIER` | empty | Optional service tier for final requests. |

This mode can improve final quality, but changing providers between a draft and
its final caption can also change wording abruptly. Rehearse with noisy,
real-event transcripts before enabling it.

### Fallback provider

When `FALLBACK_API_KEY` is present, the server sends final captions to this
provider after a primary timeout or failure:

| Variable | Default | Description |
| --- | --- | --- |
| `FALLBACK_API_KEY` | empty / disabled | Enables failover. |
| `FALLBACK_BASE_URL` | `https://api.openai.com/v1` | Fallback API root. |
| `FALLBACK_MODEL` | `gpt-4.1-mini` | Fallback model. |
| `FALLBACK_EXTRA_BODY` | empty object | JSON fields merged into fallback requests. |

Example with a compatible primary and OpenAI fallback:

```dotenv
OPENAI_BASE_URL=https://provider.example.com/v1
OPENAI_API_KEY=primary-key
OPENAI_MODEL=fast-model

FALLBACK_BASE_URL=https://api.openai.com/v1
FALLBACK_API_KEY=sk-fallback-key
FALLBACK_MODEL=gpt-4.1-mini
```

Provider fallback improves availability but does not make the app independent
of third-party rate limits. Use credentials with sufficient request and token
quotas for the number of live rooms.

## Speech recognition

| Variable | Default | Description |
| --- | --- | --- |
| `DG_ENDPOINTING` | `300` | Approximate silence in milliseconds before Deepgram closes an utterance. |
| `DG_PT_LANGUAGE` | `multi` | Deepgram language mode for Portuguese input. |
| `STT_PROXY` | `true` | Route audio through the app server instead of connecting the browser directly to Deepgram. |

Supported Portuguese language values:

- `multi`: Nova-3 multilingual behavior; recommended when Portuguese speech
  contains English technical terms
- `pt-BR`: Portuguese-specific behavior for deployments that prefer it

Lower endpointing values close phrases sooner but may split sentences. Higher
values provide more context but delay final captions. Rehearse in the real room
before changing the default.

With `STT_PROXY=true`, the browser sends 16 kHz PCM audio to the app WebSocket,
and the app owns the Deepgram connection. This is the simplest operational
mode and is required by `scripts/latency-test.mjs`.

With `STT_PROXY=false`, the browser requests a short-lived Deepgram grant token
from the app and opens the Deepgram WebSocket directly. The long-lived
Deepgram API key still remains server-side. The Deepgram key must be allowed to
call the `/v1/auth/grant` endpoint.

## Caption cadence

| Variable | Default | Description |
| --- | --- | --- |
| `LIVE_DRAFTS` | `true` | Translate interim speech instead of waiting only for final phrases. |
| `DRAFT_INTERVAL_MS` | `350` | Minimum interval between draft translation attempts for a room. |
| `DRAFTS_PER_SECOND` | `15` | Global draft request budget shared across all rooms. |

Drafts make the screen feel responsive but create substantially more provider
requests. If the provider returns HTTP 429 responses:

1. lower `DRAFTS_PER_SECOND`;
2. increase `DRAFT_INTERVAL_MS`;
3. confirm account rate and token limits;
4. set `LIVE_DRAFTS=false` if finalized-only captions are acceptable.

The provider may return interim transcripts less frequently than
`DRAFT_INTERVAL_MS`; reducing this value cannot make Deepgram emit transcripts
faster.

## Vocabulary files

All files are UTF-8 text and support blank lines and comments beginning with
`#`. Restart the app after editing them.

### `config/keyterms.txt`

One important term per line:

```text
PostgreSQL
WAL
pgvector
```

Terms are sent to Deepgram and are also protected in translation prompts. Keep
the list focused; an excessively broad list can hurt recognition.

### `config/aliases.txt`

Map a canonical spelling to comma-separated recognition mistakes:

```text
Patroni = patrone, patrono
etcd = e t c d, t c d
```

Aliases are applied to whole words or phrases before both draft and final
translation. Build this list from real transcripts.

### `config/glossary.txt`

Provide context only when a term appears:

```text
banco: when discussing databases, translate as database
replica: a PostgreSQL standby or read replica
```

Format each entry as `term: explanation`.

## Test-script settings

Diagnostic scripts optionally read `.env.test`, which is intentionally ignored
by Git. Create it from `.env.test.example`:

```bash
cp .env.test.example .env.test
chmod 600 .env.test
```

| Variable | Used by | Description |
| --- | --- | --- |
| `LC_CAPTURE_URL` | `latency-test.mjs` | Private capture URL for the test room. |
| `LC_ROOM_URLS` | `rooms-status.mjs` | Comma-separated private capture URLs. |

Never put real room URLs into `.env.test.example`.

## Applying changes

Environment variables are read only at process startup:

```bash
docker compose up -d --force-recreate app
```

Vocabulary files are mounted read-only into the container, but the app still
loads them only at startup, so the same restart is required.

Before restarting during an event, use `node scripts/rooms-status.mjs` and
confirm no room is actively capturing. Current captions and transcripts are
in-memory and are cleared by a restart.
